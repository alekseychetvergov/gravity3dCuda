# 🌌 Высокопроизводительная 3D-симуляция гравитации N тел на CUDA и CMake

Реализация высокооптимизированной симуляции физики гравитационного взаимодействия N тел (задача N-body). Проект использует архитектуру **NVIDIA CUDA** для массово-параллельных вычислений на GPU, собирается через кроссплатформенный инструмент **CMake** и верифицируется с помощью фреймворка **GoogleTest (GTest)**.

## 📐 Математическая модель и алгоритм

В основе симуляции лежит классический закон всемирного тяготения Ньютона с добавлением фактора сглаживания (Softening Factor) для предотвращения деления на ноль при критическом сближении частиц.

### Формулы расчета
Суммарная сила \(\vec{F}_i\), действующая на \(i\)-е тело со стороны всех остальных \(N-1\) тел, вычисляется как:

\[\vec{F}_i = G \cdot m_i \sum_{j \neq i}^{N} \frac{m_j (\vec{r}_j - \vec{r}_i)}{\left( \Vert{}\vec{r}_j - \vec{r}_i\Vert{}^2 + \varepsilon^2 \right)^{3/2}}\]

где:
*   \(G\) — гравитационная постоянная;
*   \(m_i, m_j\) — массы взаимодействующих тел;
*   \(\vec{r}_i, \vec{r}_j\) — радиус-векторы координат тел в 3D-пространстве;
*   \(\varepsilon^2 = 10^{-9}\) — параметр сглаживания, исключающий сингулярность при \(\vec{r}_j \to \vec{r}_i\).

Для обновления скоростей и координат на каждом шаге времени \(\Delta t\) используется метод Эйлера:

\[\vec{v}_i(t + \Delta t) = \vec{v}_i(t) + \frac{\vec{F}_i}{m_i} \Delta t\]

\[\vec{r}_i(t + \Delta t) = \vec{r}_i(t) + \vec{v}_i(t + \Delta t) \Delta t\]

### Алгоритм работы на GPU
Вычислительная сложность прямого метода «каждый с каждым» составляет \(O(N^2)\) операций на один шаг времени. На GPU задача распараллеливается следующим образом:
1.  **Инициализация:** На хосте (CPU) генерируются начальные координаты тел. Данные упаковываются в массив структур `double3` и копируются в глобальную память видеокарты.
2.  **Расчет сил (`computeGravityForcesKernel`):** Запускается сетка из \(N\) потоков (по одному CUDA-потоку на каждое тело). Каждый поток загружает координаты своего тела в быструю регистровую память и в цикле проходит по всем остальным телам, накапливая результирующий вектор силы в локальной переменной.
3.  **Интегрирование (`updatePositionsKernel`):** После синхронизации потоков второй кернел параллельно для всех \(N\) тел вычисляет новые векторы скорости и обновляет пространственные координаты.
4.  **Цикл симуляции:** Шаги 2 и 3 повторяются заданное количество раз (`STEPS`) непосредственно в памяти GPU без лишних пересылок данных на CPU.
5.  **Выгрузка результатов:** По завершении всех шагов итоговые координаты копируются обратно в оперативную память хоста.

## 🚀 Ключевые оптимизации

*   **Аппаратный интринсик `rsqrt()`:** Вычисление множителя \(\left( \Vert{}\vec{r}_j - \vec{r}_i\Vert{}^2 + \varepsilon^2 \right)^{-3/2}\) реализовано через быстрый обратный квадратный корень `rsqrt(distSqr)` с последующим возведением в куб. Это избавляет от медленных вызовов `std::sqrt` и `std::pow`.
*   **Отказ от `atomicAdd`:** Переход к модели «один поток — одно тело» полностью исключил конкуренцию потоков при записи в глобальную память и убрал необходимость в дорогостоящих атомарных операциях.
*   **Локальность данных (`double3`):** Координаты, скорости и силы хранятся в выровненных векторных структурах `double3`, что оптимизирует работу с кэш-линиями видеокарты.
*   **Безопасное управление памятью (RAII):** Жизненный цикл буферов на хосте и устройстве контролируется стандартными контейнерами C++ (`std::vector`), что исключает утечки памяти.

```text
gravity3dCuda/

├── README.md               # Документация проекта

│   └── gravity3dCuda.hpp   # Заголовочный файл с интерфейсом для хоста
```

## 🛠️ Системные требования

*   **Операционная система:** Windows 10/11 или Linux
*   **Компилятор хоста:** MSVC v142 (Visual Studio 2019) / v143 (Visual Studio 2022) или GCC 11+
*   **CUDA Toolkit:** Версия 12.0 или новее
*   **Система сборки:** CMake версии 3.22+

## 🔨 Сборка и запуск проекта

### Вариант 1. Сборка через консоль (CLI)

#### Для Windows (Developer Command Prompt / PowerShell для VS):
```bash
# 1. Создаем директорию для сборки и переходим в нее
mkdir build
cd build

# 2. Конфигурируем проект с указанием стабильного тулсета v142 или v143
cmake .. -G "Visual Studio 17 2022" -A x64 -T "v142"

# 3. Компилируем в режиме Release для максимальной производительности
cmake --build . --config Release

# 4. Запуск симуляции
.\Release\gravity3d_run.exe

# 5. Запуск модульных тестов
.\Release\gravity3d_tests.exe
```

#### Для Linux (Ubuntu/Debian):
```bash
mkdir build
cd build
cmake .. -DCMAKE_BUILD_TYPE=Release
cmake --build . --parallel $(nproc)
./gravity3d_run
./gravity3d_tests
```

### Вариант 2. Сборка через Visual Studio
1. Откройте Visual Studio и выберите **«Открытие локальной папки»** (Open a local folder).
2. Укажите корневую директорию проекта `gravity3dCuda`.
3. В верхнем меню конфигураций выберите пресет **`x64 Debug (v142 Toolset via VS Generator)`** или **`v143`**.
4. Выберите целевой файл `gravity3d_run.exe` и нажмите **F5**. Для запуска тестов откройте **Тест** ➡️ **Обозреватель тестов** и нажмите **Запустить все**.
