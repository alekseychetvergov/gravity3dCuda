# 🌌 Высокопроизводительная 3D-симуляция гравитации N тел на CUDA и CMake

Реализация высокооптимизированной симуляции физики гравитационного взаимодействия N тел (задача N-body). Проект использует архитектуру 
**NVIDIA CUDA** для массово-параллельных вычислений на GPU, собирается через кроссплатформенный инструмент **CMake** и верифицируется с 
помощью фреймворка **GoogleTest (GTest)**.

## 🚀 Ключевые улучшения и оптимизации

Этот репозиторий представляет собой полное архитектурное переосмысление старого кода симуляции. Проект доведен до стандартов современной 
коммерческой разработки и оптимизирован под максимальную скорость вычислений:

*   **Математическая оптимизация (`rsqrt`):** Тяжелые стандартные вызовы функций `std::pow` и `std::sqrt` внутри GPU-кернелов заменены на аппаратный CUDA-интринсик `rsqrt()`. Он вычисляет обратный квадратный корень за один тактовый цикл, что дало колоссальный прирост скорости при расчете сил между частицами.
*   **Устранение конкуренции потоков (Отказ от `atomicAdd`):** Старая реализация использовала атомарные операции в глобальную память на координатной сетке, что приводило к жесткой сериализации потоков. В новой версии алгоритм изменен: каждый CUDA-поток независимо аккумулирует силы, действующие на одну конкретную частицу. Это полностью исключило конфликты памяти при записи.
*   **Локальность данных и выравнивание (`double3`):** Девять раздельных host/device массивов под координаты, скорости и силы упакованы в единые эффективные векторные структуры `double3` (`pos.x`, `pos.y`, `pos.z`). Это улучшило утилизацию кэш-линий видеокарты (Cache Line Utilization) и сократило количество транзакций памяти.
*   **Безопасное управление памятью (RAII):** Из кода полностью удалены опасные сырые указатели, ручные вызовы `new[]`/`delete[]` и устаревшие C-style конструкции `goto Error`. Жизненный цикл памяти на хосте управляется STL-контейнерами, а на GPU — умными указателями `std::unique_ptr` с кастомными CUDA-делейтерами.
*   **Промышленная архитектура сборки:** Проект переведен с нативных решений Visual Studio (`.vcxproj`/`.sln`) на универсальный стандарт **CMake**. Реализовано автоматическое скачивание внешних зависимостей (FetchContent) и автоматизированное модульное тестирование.

## 📁 Структура проекта

```text
gravity3dCuda/
├── CMakeLists.txt          # Главный сценарий сборки CMake
├── CMakePresets.json       # Пресеты конфигурации для компиляторов Visual Studio
├── README.md               # Документация проекта (этот файл)
├── include/
│   └── gravity3dCuda.hpp   # Заголовочный файл с интерфейсом для хоста
├── src/
│   ├── gravity3dCuda.cu    # CUDA-кернелы и логика вычислений на GPU
│   └── main.cpp            # Точка входа, генерация сцены и замеры телеметрии
└── tests/
    └── test_gravity.cpp    # Модульные тесты физических законов на GoogleTest
```

## 🛠️ Системные требования

*   **Операционная система:** Windows 10/11 или Linux
*   **Компилятор хоста:** MSVC v142 (Visual Studio 2019) / v143 (Visual Studio 2022) или GCC 11+
*   **CUDA Toolkit:** Версия 12.0 или новее
*   **Система сборки:** CMake версии 3.22+

## 🔨 Сборка и запуск проекта

### Вариант 1. Сборка через консоль (CLI) — Рекомендуется для автоматизации
Для сборки проекта без открытия тяжелого интерфейса IDE, выполните следующие команды в терминале:

#### Для Windows (через Developer PowerShell / Command Prompt для VS):
```bash
# 1. Создаем отдельную директорию для сборки и переходим в нее
mkdir build
cd build

# 2. Конфигурируем проект, явно указывая стабильный тулсет v142 или v143
cmake .. -G "Visual Studio 17 2022" -A x64 -T "v142"

# 3. Запускаем компиляцию проекта в режиме Release
cmake --build . --config Release

# 4. Запуск основного бенчмарка симуляции
.\Release\gravity3d_run.exe

# 5. Запуск модульных тестов
.\Release\gravity3d_tests.exe
```

#### Для Linux (Ubuntu/CentOS):
```bash
mkdir build
cd build

# Конфигурируем проект с дефолтным компилятором GCC
cmake .. -DCMAKE_BUILD_TYPE=Release

# Собираем проект, задействуя все доступные ядра процессора
cmake --build . --parallel $(nproc)

# Запуск приложений
./gravity3d_run
./gravity3d_tests
```

### Вариант 2. Сборка через графический интерфейс Visual Studio
1. Запустите Visual Studio и выберите пункт **«Открытие локальной папки»** (Open a local folder).
2. Укажите корневую директорию проекта `gravity3dCuda`.
3. В верхнем выпадающем меню конфигураций выберите пресет **`x64 Debug (v142 Toolset via VS Generator)`** или аналогичный `v143`. Это изолирует сборку от нестабильных экспериментальных инструментов вашей среды.
4. Выберите `gravity3d_run.exe` в качестве целевого объекта сборки и нажмите **F5** для запуска бенчмарка.
